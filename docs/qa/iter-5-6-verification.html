Iter-5 — Task 5.1: BrainstormEngine + CoolingTimer
backend/app/services/brainstorm.py — 讨论引擎核心
3
CoolingTimer 状态机 — 4 状态转换
RUNNING → (idle >= cooldown_seconds) → COOLING_DOWN → (idle >= cooldown + confirmation) → CONFIRMING → (idle in state >= confirmation) → ENDED。
新发言 / user message → 重置到 RUNNING。message_count >= max_messages → ENDED。
使用 time.monotonic() 而非 asyncio time。
4
CoolingTimer — heartbeat() vs keep_alive() 职责分离
heartbeat(): agent 发言保存入库后调用，重置空闲计时器 + 递增 message_count。
keep_alive(): agent 开始生成时调用（agent_start 后），仅重置空闲计时器，不递增 count。
防止 LLM 调用耗时（5-30s）被误判为空闲，错误触发冷却。
5
BrainstormEngine — 多轮循环架构 (MAX_ROUNDS=8)
_run_rounds(): while sub_round < MAX_ROUNDS 循环，每轮所有 Agent 顺序发言。
全员 PASS（speeches_this_round == 0）→ 自然结束。
每个 Agent 可见完整对话历史（含本轮前序 Agent 的响应）。
互动式 Prompt：针对最新发言回应，可点名反驳、追问；无新内容时发 PASS。
6
PASS 机制 — Agent 回复 "PASS" 不入库
Agent 回复纯文本 "PASS"（大小写不敏感）→ 发送 agent_pass SSE 事件，消息不持久化到 DB。
空内容也视为 PASS。agent_pass 事件携带 agent_id, agent_name, agent_number。
7
LLM 错误处理 — Agent 失败不阻断讨论
单个 Agent LLM 调用失败 → 捕获异常 → 发送含错误信息的 agent_token → 继续下一个 Agent。
不中断整个讨论流程。错误内容截断到 100 字符。

Iter-6 — Task 6.0: 后端持久连接
backend — run_persistent() + /connect + /inject 端点
15
POST /connect — 建立持久 SSE 连接
创建 BrainstormEngine → 注册到 _active_connections[session_id] → 返回 SSE 流。
连接已存在时先 abort 旧连接。会话不存在 → 404，已 ended → 400。
SSE 流由 engine.run_persistent() 驱动，空闲 30s 发送 heartbeat。
16
POST /inject — 注入用户消息（非阻塞 202）
Body: {"content": "...", "reply_to_message_id": null}。
查找 _active_connections 中的 engine → 调用 engine.inject()。
无活跃引擎 → 400（"No active connection"）。会话已 ended → 400。
返回 {"status": "injected"}，立即返回不等待 agent 响应。
17
DELETE /connect — 优雅关闭
从 _active_connections 移除 engine → 调用 engine.abort()。
返回 {"status": "disconnected"}。engine 的 run_persistent() 循环退出 → SSE 流关闭。
无活跃引擎时静默返回。
18
run_persistent() — queue-driven 持久循环
while not self._abort 循环等待 queue.get()（30s 超时 → heartbeat）。
收到消息 → 保存入库 → 推送 user_message SSE → _run_rounds()。
_run_rounds() 结束后回到等待状态，连接保持。
queue 非空时 break 当前 agent 循环，优先处理新消息。
19
Agent 列表热重载 — 每条消息重新加载
run_persistent() 在每条 inject 消息处理前调用 _load_agents()。
运行中添加/移除 Agent 在下一条消息起生效，无需断开重连。
初始空团队检查保留（连接建立时）。
20
SSE 事件 — user_message / round_end / heartbeat
user_message: {message_id, content, parent_message_id} — 用户消息已入库。
round_end: {round, speeches} — 本轮结束，连接保持。
heartbeat: {} — 空闲 30s 心跳。
这 3 个事件为 Iter-6 新增，与 Iter-5 的 7 个事件共 10 个。
Iter-6 — Task 6.1: 前端 Store 重构
frontend/src/stores/brainstormStore.ts — 持久连接模型
21
connectSession / disconnectSession / injectMessage
connectSession: POST /connect → 建立持久 SSE → discussionConnected = true。
disconnectSession: abort 控制器 + DELETE /connect → 清空状态。
injectMessage: POST /inject → 立即返回，不等待 agent 响应。
发消息只调 injectMessage，不重建 SSE 连接。
22
discussionConnected vs discussionActive 语义区分
discussionConnected: SSE 连接是否活跃（进入 brainstorm 模式即建立）。
discussionActive: 当前是否有 agent 正在生成内容（user_message 后 true，discussion_end 后 false）。
两者共存，语义不同。前端同时检查两者（如 Stop 按钮显示条件）。
23
Session 切换状态清空 — 防止跨会话消息污染
activateSession() 切换 session 时清空：discussionMessages, discussionActive, activeAgentId, activeAgentName, activeAgentNumber, streamingContent。
防止原 session 的消息显示在新 session 界面上。
24
user_message 事件 — 乐观更新替换
前端发送消息时立即显示 temp-{timestamp} 占位消息。
收到 user_message SSE 事件后，查找最新 temp-human 消息并替换为真实 ID。
无 temp 消息时直接追加。

Iter-6 — Task 6.3: 彩色线程竖线

28
getRootId() — 沿 parent_message_id 链找到根消息
遍历 parent_message_id 链直到无 parent 的祖先。visited Set 检测循环。

29
threadColor() — FNV-1a hash → HSL 色值
FNV-1a hash（offset basis 2166136261, prime 16777619）% 360 → 色相。
返回 hsl(hue, 45%, 58%)。同一根消息的所有 reply 共享同一颜色。
不同根消息大概率不同颜色。
30
