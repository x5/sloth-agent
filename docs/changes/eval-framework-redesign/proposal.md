# 变更提案: Evals 评估框架重新设计

> 日期: 2026-05-02
> 影响模块: cli/eval/spec.md

## 动机

当前 evals 模块只有一个骨架：1 个 eval task、1 个只验证 plan 文件是否存在的 runner、1 个 mock pipeline 冒烟测试。无法真正评测 Agent 能力，也无法跟踪版本间的能力变化。

需要一个成熟的评估框架，参考业界 GAIA（通用能力评测、难度分级）和 SWE-bench（真实任务执行、自动验证）的设计理念，为 Sloth Agent 建立完整的评测体系。

## 范围

- 重新设计 eval runner，复用 Sloth 流水线执行真实任务
- 引入四维度加权评分模型（正确性、产出质量、过程效率、部署产物）
- 支持 L1/L2/L3 三级难度分级
- 支持版本间结果对比
- CLI 入口集成到 sloth 命令

## 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 用途 | 回归测试 + 能力基准 | 大版本时跑，两者兼顾 |
| LLM | 真实 LLM | 只在大版本跑，结果可信 |
| 验证方式 | 多维度评分 | Gate 通过率 + 产出质量 + 过程效率 + 部署产物 |
| 部署评测 | 只评产物不真部署 | 可控、可重复、不需要外部依赖 |
| Task 管理 | YAML 索引 + 独立 Plan 文件 | 保持现有结构，扩展元数据 |
| 结果存储 | JSON 文件按版本号命名 | 和"文件系统即真相"原则一致 |
| Runner 架构 | 流水线级 Eval（方案 A） | 最简单，完全复用现有基础设施 |
